## 先说结论

- AI Agent 要“自己花钱”，需要三样东西：**钱包、权限、支付协议**。
- Agentic Wallet 解决“Agent 用什么账户”，x402 解决“怎么按次付费”，B402 Bazaar 解决“去哪里找可付费的服务”。
- 最大风险不是模型答错，而是**权限给太大、Skill 不可信、自动扣费失控**。
- 正确姿势：独立小额钱包 + 单次/每日限额 + 人工确认大额 + 定期撤销授权。

## 一、Agent 为什么需要钱包

普通聊天机器人只输出文本；Agent 要完成真实任务，需要：

- 查询付费数据；
- 调用 API/算力/存储；
- 购买服务或内容；
- 在链上执行交易。

如果没有钱包，Agent 每次都要人手动付款，自动化就断了。Agentic Wallet 就是给 Agent 的“执行账户”。

## 二、Agentic Wallet 的关键设计

币安对 Agentic Wallet 的定位是“专为 AI Agent 打造的独立钱包”。对用户来说，重点看四件事：

1. **隔离**：和主钱包分开，出事不至于全军覆没；
2. **限额**：单次、每日、单服务预算；
3. **权限**：只允许特定合约/服务/地址；
4. **可撤销**：随时停用 Agent、撤销授权、查看日志。

不要：

- 把主钱包私钥/助记词交给 Agent；
- 给无限额度；
- 让 Agent 同时拥有“读数据 + 转账 + 交易”全部权限而不审核。

## 三、x402 是什么

x402 用 HTTP 402（Payment Required）做机器支付：

1. Agent 请求一个付费 API；
2. 服务端返回 402 和价格；
3. Agent 用钱包完成支付；
4. 服务端返回数据/服务。

它适合“按次付费”的场景：行情、链上数据、AI 推理、翻译、监控、报告等。相比订阅制，x402 让 Agent 可以只为实际调用付费。

## 四、B402 Bazaar 是什么

B402 Bazaar 是 x402 服务的市场：开发者发布付费服务，Agent 发现并购买。可以理解为“Agent 的服务商店”。

使用前要确认：

- 服务方是谁，是否有文档/审计；
- 价格是否透明，是否会自动续费；
- 返回的数据是否可验证；
- 是否有退款/争议机制。

## 五、一个安全的 Agent 支付流程

1. 创建独立 Agentic Wallet，只充小额；
2. 设置单次/每日限额和允许列表；
3. 在 Skills Hub/B402 选择来源明确的服务；
4. 先用最小金额测试一次调用；
5. 人工核对返回结果和扣费；
6. 大额操作必须人工确认；
7. 任务结束撤销授权/停用 Agent。

## 六、五个高风险点

### 1. Prompt Injection

网页/API 返回的内容可能包含恶意指令，诱导 Agent 转账或泄露数据。不要给 Agent 无限制的支付权限。

### 2. 恶意 Skill

Skill 可能读取账户、调用转账、上传数据。安装前看来源、权限、审计和用户评价。

### 3. 自动扣费

按次付费可能变成高频小额扣费。设置预算和频率上限，定期看日志。

### 4. 价格/汇率操纵

服务方可能动态调价，或利用 Agent 不懂比价。给 Agent 设置价格上限。

### 5. 法律与税务

Agent 代你交易/支付，责任仍可能在你。地区限制、KYC/AML 和税务要提前确认。

## 七、适合普通人的用法

- 付费数据查询/监控；
- 自动生成日报/周报；
- 小额 API 调用；
- 测试性自动化，不接实盘大额资金。

不适合：

- 把全部资产交给 Agent；
- 用 Agent 做高杠杆合约；
- 不做预算就开放自动支付。

## 八、常见问题

**Q：Agentic Wallet 需要私钥吗？**
A：币安称其为面向 Agent 的独立钱包；具体密钥/托管机制以官方文档为准。用户不应把主钱包私钥交给 Agent。

**Q：x402 只能用在币安吗？**
A：x402 是支付协议，B402 是币安生态的市场；其他平台也可能支持类似机制。

**Q：Agent 会自动花光钱包吗？**
A：如果权限和额度不设限，有可能。必须设置预算、允许列表和人工确认。

**Q：新手适合用吗？**
A：适合先了解和小额测试，不适合直接把大额资金交给自动化 Agent。
